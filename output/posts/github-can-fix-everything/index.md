The title is a little facetious but I do think <a href="http://github.com">Github</a> <em>collaberation is not being taken advantage</em> of in the ColdFusion community. Sure some CFML-ers like <a href="https://github.com/markmandel">Mark Mandel</a>, <a href="https://github.com/lmajano">Luis Majano</a>, and <a href="https://github.com/marcesher">Marc Esher</a> are using github. ColdFusion projects like <a href="https://github.com/ValidateThis">ValidateThis</a>, <a href="https://github.com/seancorfield/fw1">FW1</a>, and <a href="https://github.com/blueriver/MuraCMS">MuraCMS</a> are on it. <a href="http://bittersweetryan.github.com/ColdFusion-Koans/">ColdFusion Koans</a> is even taking advantage of <a href="http://pages.github.com/">github pages</a> (being able to host a site on github). All this said, <em>github is much more than hosting projects and sample code<strong>. </strong></em>
The Wired article, <a href="http://www.wired.com/wiredenterprise/2012/02/github-revisited/">The Meta-Story: How Wired Published Its GitHub Story on GitHub</a>, describes how Wired published a story using github. It mentions Github is being used to oversee stuff outside of code like Senate bills, text files, and books. <a href="https://github.com/progit/progit">Pro Git</a> is a great example of publishing a book on github. 
People "<em>can mess around with it, and then offer the changes back</em>". Training material is perfect for github also. I have <a href="https://github.com/mhenke/CFML-in-100-minutes/wiki">CFML in 100 minutes</a> on github. It is pretty cool a couple weeks ago <a href="https://github.com/bcswartz">bcswartz</a> added a <strong>Switch, Case, &amp; Default </strong>section. I did change the sections to a wiki from markdown files. 
Back to my original point, the CFML community<em> doesn't seem from my perspective to be taking full advantage of Github collaberation</em> and I hope this changes.

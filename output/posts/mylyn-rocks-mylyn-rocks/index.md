I feel like I am in Battlestar Galactica when using <a href="http://eclipse.org/mylyn">Mylyn</a> to work inside Eclipse. Task focused user interface is the future and the future is now. If you are using <a href="http://cfeclipse.org/">CFEclipse</a>, you need to use Mylyn by creating local tasks. I have hooked in <a href="http://trac.edgewall.org/">Trac</a> and <a href="http://subversion.tigris.org/">Subversion</a> @ work but the neat thing with Mylyn is you don't need to connect your ticket and code repositories. I have watched the <a href="http://live.eclipse.org/node/412">Mylyn 2.2 Adobe Connect presentation</a>, five times now and pick up multiple cool things each time.<br />
<br />
<strong>Mylyn reduces the IDE information overload. <em>Program more</em> and search, scroll, navigate less.</strong>
<em>**Update 4/6/2008**</em>
<em>A comment was left on <a href="http://www.dzone.com/links/mylyn_rocks_mylyn_rocks.html">dzone.com</a> about this post so I try to add more detail but please check out the Mylyn links above and watch the presentation. This post wasn't meant as a tutorial just my announcement how much Mylyn Rocks :-)</em>
<ul>
 <li><strong>no source control/ticket repository Mylyn still beneficial</strong>
 <ul>
 <li>degree of interest weighting - meaning when working on a ticket you see only the relevent resources which are put into levels (landmark, interesting, uninteresting)</li>
 <li>makes multitasking easy since you can pick up exactly where you left off with one click</li>
 <li>focused workweek - even your task list maybe come overloaded so this helps so only the relevent tasks show</li>
 <li>scheduled - soft events, own work week, planned start dates</li>
 </ul>
 </li>
 <li><strong>connection with source control/ticket repository</strong>
 <ul>
 <li>task context sharing - easily attach / retreive task content from tickets so anyone will be able to pickup with the relevent files</li>
 <li>work with tickets inside Eclipse - no need to go to ticket system for updates and modification of tickets.</li>
 <li>offline support - work with tickets is stored until synchronization so you can update tickets offline</li>
 </ul>
 </li>
</ul>

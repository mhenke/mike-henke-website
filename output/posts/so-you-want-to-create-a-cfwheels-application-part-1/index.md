Lets look @ the files installed with CFWheels, talk about Request Handling ,and URL Rewriting.<h3>Directory Structure</h3>We will cover the ones, I consider important :-) These folders are directly under the webroot. Here is a detailed list of <a id="j74t" title="CFWheels files and folders" href="http://cfwheels.org/docs/chapter/directory-structure">CFWheels files and folders</a>.<br /><br />wheels - most important and you probably should never touch it. It is the framework heart. If upgrading, you would drop the new version of this folder into your webroot, overwriting the old version.<br /><br />controllers - brains of our application. It decides what models need to be called for data and which view to display. These will be cfc files.<br /><br />models - handle how data is read and written to our database. CFWheels creates objects to represent things in our database. These will be cfc files.<br /><br />views - our web pages presented to the user. These will be cfm files.<br /><br />config - here is our configuration. You can override some conventions here. Override Conventions? Yeah, CFWheels tries to decrease our decisions so we can focus on the important stuff but is still flexible if your heart desires. We will eventually set some things like routes, what environment we are in (development, production, etc), and maybe a database connection.<br /><br />images - images will go here and only here. No decisions, you can focus on your critical decisions.<br /><br />javascripts - javascript files will go here. Same thing, no thought, simple huh?<br /><br />stylesheets - cascading style sheets are put here. Enjoy, embrace <a id="p3kz" title="convention over configuration" href="http://en.wikipedia.org/wiki/Convention_over_configuration">convention over configuration</a>.<h3>Request Handling</h3>CFWheels maps requests to your code. Think <a id="cp:1" title="REST" href="http://en.wikipedia.org/wiki/Representational_State_Transfer">REST</a>-like. CFWheels will most likely use a "partial URL Rewrite" to access your application. For our contact application, the URL may look something like this 
```coldfusion
http://localhost/index.cfm/contact/list
```
. This will list our contacts. If your web server doesn't support cgi.path_info, you may get something like this 
```coldfusion
http://localhost/index.cfm?controller=contact&action=list
```
<h3>URL Rewriting</h3>That partial URL Rewrite is nice but how about 
```coldfusion
http://localhost/contact/list
```
? This is possible if you are using Apache or IIS, sorry built in web services with JRUN or Tomcat. You can still get the goodness of convention over configuration so don't worry.<br /><br />To see how to setup URL Rewriting, read <a href="http://cfwheels.org/docs/chapter/url-rewriting">this</a>.<br /><br />For adding an ISAPI Filter in IIS 7, check out <a id="cg:g" title="this" href="http://technet.microsoft.com/en-us/library/cc754174%28WS.10%29.aspx">this</a>.
